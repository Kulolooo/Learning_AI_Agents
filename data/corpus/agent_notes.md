# 智能体的最小闭环

一个智能体（agent）在工程上可以还原成三步循环：读取上下文、决定下一步动作、执行动作并把结果写回上下文。这个循环重复到任务完成或触发终止条件。

循环的关键不在于"模型有多聪明"，而在于**状态如何被表示**。上下文就是状态：系统提示给出角色与约束，历史消息给出做过什么，工具返回给出世界现在的样子。任何一处缺失，模型都只能用想象填补。

常见的终止条件有四类：模型主动给出最终答复；达到步数上限；token 或时间预算耗尽；检测到重复调用（同一工具同一参数连续出现）。四类终止条件应当同时存在，因为它们的失效模式互不重叠——前两类防"想太久"，后两类防"绕圈子"。

循环里最容易忽略的是错误处理。工具失败不应该抛异常终止整个流程，而应当作为一条观察结果回灌给模型，让它有机会换参数、换工具或坦白失败。把错误当数据，是把原型变成可用系统的第一个分水岭。

另一个细节是轨迹。每一步的输入摘要、模型输出、工具调用与耗时都应当落盘。没有轨迹就没有排障，也没有评估：你无法改进一个看不见的过程。

# 工具设计的原则

工具不是 API 的简单封装。模型看不到你的代码，只能看到名字、描述和参数 schema，因此这三个部分就是全部的"用户界面"。

第一，名字要动词开头、语义单一，例如 `get_order_status` 而不是 `order`。第二，描述要写清楚"什么时候用"而不只是"做什么"，并显式写出返回值的形状。第三，参数要少而必要；超过五个参数通常说明这个工具承担了过多职责，应当拆分。

参数校验必须在执行前完成。缺少必填项、类型不符、出现未声明的字段，都应当返回结构化错误而不是静默忽略。静默忽略会让模型以为调用成功，进而在错误的前提上继续推理。

副作用工具需要单独的标记与审批通道。查询类工具可以随意重试，转账、发邮件、删数据这类操作必须有幂等键或人工确认。把 `side_effect` 写进工具声明，是最省事的做法：审批门、审计日志、灰度开关都能挂在这一个字段上。

工具返回的内容也要控制长度。一个返回两千行日志的工具会瞬间吃掉上下文预算，还会稀释真正重要的信息。截断并在末尾标注"已截断"，比让模型自己在噪音里找信号要好。

并行调用是性能优化的常见手段，但要注意副作用工具不能并行执行，且并行结果必须按请求顺序回填，否则模型会把两条观察对错号。

# 检索增强与评估

检索增强生成（RAG）的价值在于把"模型记忆"换成"可核验的资料"。整条链路是：切分文档、建立索引、检索候选、重排、拼接上下文、生成带引用的答案。

切分策略直接影响上限。切得太碎，单个片段缺少上下文，答案会断章取义；切得太大，检索精度下降，还会浪费预算。实践中的折中是按句子边界切分，块长控制在 200 到 400 字，相邻块保留 10% 到 20% 的重叠。

检索需要两路信号。BM25 擅长精确词匹配，比如产品型号、错误码、专有名词；向量检索擅长语义近似，比如同义改写。用倒数排名融合（RRF）合并两路结果，不需要把两种分数校准到同一量纲，工程上最省心。

重排是廉价的第二次机会。用词项覆盖率或交叉编码器对前若干候选重新打分，通常能修正一部分排序错误。重排的收益在候选集较小时最明显。

评估要盯住三个指标：召回率（相关资料是否被检出来）、引用覆盖率（答案是否标注了来源）、忠实度（答案是否只使用了资料里的内容）。前两个可以规则化，第三个通常需要模型评审或人工抽检。

没有评估的 RAG 只是一个演示。把测试问题、期望引用的块 id 和期望答案要点写成固定用例，每次改动后重跑，才能知道这次调整是进步还是退步。

# 记忆的写入成本

记忆系统的难点不在存储，而在决定"什么值得记"。写入是昂贵的：抽取事实要调用模型，去重要做相似度比较，冲突要判断以谁为准。读取消成本相对固定，但召回太多会污染上下文。

一个可用的分层是：工作记忆保存最近若干轮对话；语义记忆保存稳定的偏好与事实；情景记忆保存"某次任务怎么做的、结果如何"。三层各有各的淘汰策略，工作记忆按轮数滑动，语义记忆按重要度与时间衰减，情景记忆按任务相似度召回。

写入策略可以用重要度阈值来简化：只有重要度超过阈值的候选才进入长期记忆。重要度可以由规则给出（是否包含数字、人名、明确偏好），也可以由模型打分。阈值化的好处是成本可控，坏处是可能漏记，因此需要保留"手工写入"的通道。

冲突处理常被忽略。用户上周说偏好邮件，这周说偏好电话，两条记忆不能同时生效。常见做法是给每条记忆带时间戳与置信度，读取时按"新近度 × 置信度"排序，并在提示里显式标注"以最新一条为准"。

记忆还需要遗忘。过期的事实比没有事实更危险，因为它会让模型自信地给出错误答案。给记忆设置有效期，或者在读取时把时间戳一并交给模型，是两种低成本的缓解手段。
